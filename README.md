## 简介

**qi-bunny(奇小兔)** 是面向 AI 智能体开发场景的开源库获取辅助工具:智能体在开发过程中需要频繁搜索、克隆、更新 GitHub 上的开源仓库与依赖资源,当 GitHub 访问缓慢或不稳定时,本工具通过本机 SNI 反向代理 + SSH 转发保障这一工作流:

- **HTTPS 加速**:启动即把 GitHub 域名指向 `127.0.0.1`,由**本机 SNI 反向代理**承载全部 HTTPS 流量
- **代码库管理模式(SSH)**:本地端口转发承载 `git push / git pull`,解决"网页能打开、库更新/推送不上去"的问题
- **托盘驻留**:启动后缩到系统托盘,图标即状态,菜单即控制

程序完全本地运行,不依赖任何第三方代理服务器;TLS 流量**端到端透传**(不解密、不替换证书,证书校验仍由浏览器完成),所有候选上游 IP 均经过真实 TLS 握手验证。

## 功能特性

### 多通道候选 IP 采集(五路独立来源)

任何一路被干扰时其余几路自动补位:

| 来源 | 说明 |
|---|---|
| 多路 DoH | DNSPod / AliDNS 共 6 个加密端点并行查询 |
| UDP 53 DNS | 3 个国内公共 DNS,DoH 全挂时兜底 |
| IPv6(AAAA) | 与 IPv4 同时采集,扩充地址池 |
| GitHub 官方 meta API | 官方公布网段采样,权威可靠 |
| ipaddress.com | 第三方历史解析记录抓取 |

另有**last-known-good 缓存**(成功 IP 记盘,下次优先参选,DNS 异常时也有可用起点)。

### 加速链路

```
五路采集 → 全池 TLS 测速 → 写 hosts(127.0.0.1)→ 本机 SNI 反代接管 → 自动 flushdns
                                        ↓
        5 分钟定期自检,失效自动重新测速恢复 ←── 每连接动态择路 + 后台周期探测
```

- **真实 TLS 握手测速**:只采用验证可用的 IP,拒绝"DNS 说通、实际被断"的假可用(403 滥用拦截页同样被过滤)
- **每连接动态择路**:每条新连接从健康池挑选最优上游,连不上 2.5 秒内立即换下一个候选——单 IP 中途被限速/拉黑只影响当前连接,不再出现"测速通过、用着用着全挂"
- **后台周期探测**:每 2 分钟重测健康候选、按延迟重排,探测未通过(含 403 拦截)的候选立即出局;健康候选不足时自动重新采集外部候选补充
- **端到端 TLS 透传**:本机代理解析 ClientHello 的 SNI 后原样转发字节,不解密流量,浏览器证书校验不受影响,无需安装根证书
- **定期自检与自动恢复**:加速开启时每 5 分钟验证链路,失效(hosts 块丢失或 GitHub 不可达)自动重新测速恢复——全程无需人工干预

### 托盘交互

- 🟢 **亮色图标**(品牌绿)= 加速已开启
- ⚪ **灰色图标** = 加速关闭 / 开启失败
- 菜单项:**开启加速 / 关闭加速 / 重新测速并刷新 / 代码库管理模式 / 退出**

## 使用指南

### 前置要求

- **Windows**(需管理员权限运行,以写入 hosts)
- 使用代码库管理模式需已安装 OpenSSH 客户端(Win10/11 自带)

### 快速开始

**方式一:托盘模式(推荐)**

右键"以管理员身份运行" `qi-bunny.exe`(或不带参数):

```
qi-bunny.exe
```

程序驻留系统托盘并自动开启加速:启动即测速写入 hosts,由本机反代接管 GitHub 访问。点击托盘图标弹出菜单:

| 菜单项 | 作用 |
|---|---|
| 开启加速 / 关闭加速 | 手动开关 HTTPS 浏览加速(自动模式之外的手动兜底) |
| 重新测速并刷新 | 某域名打不开时手动换 IP |
| 代码库管理模式 | 勾选开启,让 `git push/pull` 走加速链路 |
| 退出 | 自动取消代理、还原 ssh config |

**方式二:命令行模式**

命令行模式与托盘模式完全独立:由独立的控制台程序 `qi-bunny-cli.exe` 提供,在命令窗口手动启动执行,与托盘程序互不关联(可分别使用)。

```
qi-bunny-cli start    # HTTPS 加速:测速写入 hosts,本机反代接管(默认)
qi-bunny-cli stop     # 手动取消加速:移除 hosts / ssh config 标记块
qi-bunny-cli git      # 代码库管理模式:SSH 转发,关闭窗口即还原
qi-bunny-cli status   # 查看加速状态(hosts / ssh config)
qi-bunny-cli clean    # 清理全部记录(hosts + ssh config,含旧版残留)
qi-bunny-cli help     # 帮助(亦支持 -h/--help/-V/--version)
```

### 典型场景

**场景 1:GitHub 打不开 / 打开慢**

以管理员身份运行,程序把 GitHub 域名指向本机,由 SNI 反代接管,等图标变亮即可。浏览器若仍不生效,程序已自动 flushdns,必要时重启浏览器。

**场景 2:git clone/pull HTTPS 远端**

保持托盘加速开启即可,HTTPS 远端自动走加速。

**场景 3:git push / SSH 远端推拉代码**

勾选托盘菜单「代码库管理模式」,程序将:

1. 探测 22 端口真正可用的 GitHub IP(校验 SSH banner)
2. 本地 `127.0.0.1:2222` 转发到该 IP,并改写 `~/.ssh/config`
3. 22 端口全部被阻断时,自动回退官方 `ssh.github.com:443` 通道

之后 `git push` / `git pull` 正常操作即可;取消勾选自动还原配置。

**场景 4:程序被强杀留下残留**

```
qi-bunny-cli clean
```

一键移除 hosts 标记块与 ssh config 标记块,恢复原状。

## 原理说明

本工具的加速机制:启动即把 GitHub 域名指向 `127.0.0.1`,由**本机 SNI 反向代理**承载 HTTPS 流量:代理解析 TLS ClientHello 中的 SNI 识别目标域名,把整条 TLS 流量**端到端透传**到健康上游 IP(不解密,证书校验仍由浏览器完成),每条连接动态挑选最优上游、失败自动换路;代码库管理模式再以 SSH 本地端口转发承载 `git push/pull`。全部功能均在本地完成,不依赖第三方代理服务器。

质量保障机制:多通道候选采集、真实 TLS 握手测速(过滤 403 滥用拦截)、每连接动态择路、后台周期探测换血、last-known-good 缓存与 5 分钟自检恢复,层层保障链路质量。

## 证书说明

本工具的 HTTPS 加速默认**端到端 TLS 透传**,不安装任何根证书,浏览器证书校验不受影响。程序目录下出现的 `qi-bunny-ca.pem` / `qi-bunny-ca.key` 是程序自带的本地 CA,仅在特定场景使用。

### 浏览器提示"不安全证书"怎么办?

若开启加速后浏览器提示证书不受信任,通常是**历史上安装过本工具的旧版 CA,而程序目录下的 CA 已重新生成**,两张证书指纹不一致导致。修复方法:

1. **清理旧 CA**:打开「管理受信任的根证书颁发机构」(`certmgr.msc` → 受信任的根证书颁发机构 → 证书;`certlm.msc` 为本机库),删除所有颁发者为 `qi-bunny Local CA` 的旧证书;
2. **安装当前 CA**:双击程序目录下的 `qi-bunny-ca.pem` → 安装证书 → 当前用户 → 「将所有的证书都放入下列存储」→ 选择**受信任的根证书颁发机构** → 完成后重启浏览器;

或用命令行(管理员):

```
certutil -addstore -f Root qi-bunny-ca.pem
```

### 已知问题:安全软件拦截证书写入

360 安全卫士、火绒等安全软件可能**静默拦截对"受信任的根证书颁发机构"的写入**——`certutil`、PowerShell、证书向导全部报"拒绝访问",即使以管理员身份运行也一样。此时请先**退出安全软件**再执行安装,完成后可重新开启。

### 如何核对 CA 是否一致

```
certutil -hashfile qi-bunny-ca.pem SHA256     # 程序当前 CA 的指纹
certutil -store Root | findstr /C:"qi-bunny"  # 信任库中已装的 CA
```

两者对应的证书须为同一张(指纹一致);若不一致,按上面的方法清理重装即可。

## 常见问题

**Q:提示"写入 hosts 失败"?**
未以管理员身份运行。右键程序选择"以管理员身份运行",或用 `sudo`(Linux)。

**Q:图标亮了但个别域名还是打不开?**
该域名当前所有候选 IP 均被网络阻断(程序宁可跳过也不写死 IP)。点击菜单「重新测速并刷新」换一批 IP;5 分钟自检也会自动重试。

**Q:git push 提示连不上?**
确认已勾选「代码库管理模式」;若提示 Permission denied,是 ssh key 未配置,与本工具无关(链路已通,已到 GitHub 认证层)。

**Q:会和 SwitchHosts 等改 hosts 的工具冲突吗?**
本工具只管理自己的标记块(`# qi-bunny begin/end`;旧版本的 `# github-proxy` 标记也会在 `clean` 时一并清理),不会动其他工具写入的内容;但多工具同时写 hosts 建议只开一个,避免互相覆盖。

**Q:退出后 hosts 会恢复吗?**
会。正常退出、关窗口、Ctrl+C 均自动清理;进程被强杀残留时用 `clean` 一键恢复。

**Q:安装 CA 时提示"拒绝访问"?**
多半是 360、火绒等安全软件在拦截对根证书库的写入,与系统权限无关。先退出安全软件再安装,详见上文[证书说明](#证书说明)。
